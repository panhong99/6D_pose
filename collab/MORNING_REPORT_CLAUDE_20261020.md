### 4. numpy(지금) vs PyRoki (Codex BN, CPU) — *아침에 Codex 최종 수치로 갱신*

| 항목 | numpy/scipy (지금) | PyRoki (JAX) | 비고 |
|---|---|---|---|
| FK 정확도 | 기준 | 차이 1e-12 mm, 6e-14° | 같은 URDF, 무작위 1000자세 |
| FK 시간 (1000자세) | 32.6 ms | 첫 호출 238 ms, 이후 2.3 ms(묶음) | PyRoki는 입력 크기마다 첫 컴파일 |
| IK 성공 (도달 가능한 목표 20개) | 20/20 | 20/20 | 적은 표본, 시작 자세 근처 시험 |
| IK 시간 (목표당 중앙값) | 13.7 ms | 1.3 ms (첫 호출 1.55 s) | |
| 운반 경로: 저장된 4조건 통과 (지금 충돌·높이·손목 검사로 판정) | 실기 성공 경로 | Q3 빨강 4/4, Q3 흰 3/3, Q4 빨강 4/4, Q4 흰 2/3 | Codex b63a9e0: 근사 캡슐 비용을 끄고 정확한 검사로만 합격 판정 |
| 운반 경로 길이 (관절 총 이동) | 143.7–174.4° | 143.9–174.5° (거의 같음) | |
| 운반 계산 시간 | 후보당 3–16 s (실패 후보 포함) | 3.7–6.3 s (첫 계산) | |
| 같은 입력 반복 | 같은 경로 (고정 시드) | 같은 경로 (변동 0°) | |

- **현재 판단**: FK/IK는 PyRoki도 정확하고 빠르다. 하지만 지금 계획 시간의 대부분은 충돌 검사라서 바꿔도 체감 효과가 작고, 실행마다 첫 컴파일 시간이 추가된다.
- 운반 경로는 정확한 충돌 검사로 합격을 정하면 PyRoki도 저장된 조건 대부분을 RRT와 같은 길이로 통과한다(시도 14개 중 13개 통과). 실기·pipeline 연결은 아직 안 했다.
- 경로 품질(매끄러움, 가속도)과 받침·바구니 위치를 바꾼 조건에서의 비교는 Codex가 계속하고 있다.
- 상세: `experiments/pyroki_bm/README.md`.

## 개선 / 결정 필요
1. **출발 물러나기 옵션을 시연에 켤지**(`plate_ik_bc.basket_carry_start_lift_m: 0.10`): 켜면 받침 띠 안 성공이 약 80% → 90%, 바구니 이동에도 더 강해진다. 시연 직전이라 **실기 계획 실행(`--execute` 없이)으로 한 번 확인한 뒤** 켤 것을 권한다.
2. **PyRoki**: 시연 뒤에 운반 충돌 모델을 맞추는 작업을 계속한다. 그때까지 시연은 지금 RRT와 경로 라이브러리를 쓴다.
3. **경로 라이브러리 주의**: Codex 비교에서 저장 경로 2개(Q3 흰, Q4 흰)가 지금 설정·최신 카메라로 재구성하면 검사에 걸렸다. 실기에서는 걸리면 RRT로 넘어가므로 멈추지 않는다. 다음 실기에서 화면에 `prior`가 나오는지 확인이 필요하다.
4. **실수 보고**: b41038d(LOG와 실험 스크립트만)를 시험이 부하 때문에 1건 시간 초과인 상태로 커밋했다. 같은 코드로 다시 돌린 시험은 95/95 통과했다.
