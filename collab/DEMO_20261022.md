# 10/22 시연 안내 (접시 → 바구니 Q3 / Q4)

10/19 오후 실기에서 Q3, Q4 모두 성공한 설정을 그대로 고정했다. 기준 코드: git 태그 `demo-20261022`.
**시연 전에는 `calibration/config.yaml`, `run.sh`, `pipeline.py`, `plate_plans.py`를 바꾸지 않는다.**

## 명령 (이것만 입력)

```bash
cd ~/pan/6D_pose
bash calibration/run.sh demo1022 Q3 --execute     # Q3: 빨강(앞쪽) → 흰색(뒤쪽)
bash calibration/run.sh demo1022 Q4 --execute     # Q4: 빨강(뒤쪽) → 흰색(앞쪽)
```

- **접시 순서는 항상 빨강 먼저, 그다음 흰색** (10/19 보스). 첫 접시로 빨간 접시를 받침에 놓는다.
- `demo1022`는 시작할 때 바구니 마커 블록을 점검한다(`BASKET OK`). **바구니가 비어 있을 때 실행한다.**
- 분면 하나에 접시 두 장을 넣는다. 끝나면 두 장을 빼고, 다음 분면을 실행한다.
- 순서는 정해져 있다. 그리퍼가 Q3에서는 접시의 먼 쪽에, Q4에서는 로봇 쪽에 있기 때문이다(10/19 보스 A).
- 칸은 자동으로 고른다. 앞쪽/뒤쪽 영역 안에서 경로가 나오는 칸이고, 두 접시는 최소 4칸 떨어진다.
- 10/19 오프라인 예상 칸: Q3 12 → 8, Q4 6 → 11.
- `--execute`를 빼면 로봇은 움직이지 않는다. 계획과 미리보기만 한다.

## 시작 전 점검 (순서대로)

1. **네트워크** (재부팅한 경우만): `sudo ip addr add 192.168.127.5/24 dev enp5s0`
2. **터미널 1, 로봇 연결**: `bash calibration/run.sh connect`. 끝날 때까지 켜 둔다.
3. **로봇 홈 자세**: 펜던트로 홈 자세에 둔다. 홈에서 벗어나 있으면 pipeline이 시작을 거부한다.
4. **바구니**: 비어 있는지, 늘 두던 자리인지 확인한다. 바구니 높이는 0.144 m로 고정했다. 테이블 위에서 옮기지 않는다.
5. **마커 4개 확인**: `bash calibration/run.sh markers` → 화면 위쪽에 `ALL 4 OK`(2, 3, 4, 5)가 뜨는지 본다 → **q로 닫는다.** 닫지 않으면 시연이 같은 카메라를 쓰지 못한다.
   - 하나라도 `--`이면 가리는 물건을 치운다. 마커 3개로 맞추면 바구니 위치가 수 cm 틀릴 수 있고, 잔차가 10 mm를 넘으면 pipeline이 움직이기 전에 멈춘다.
6. **접시 놓는 자리**: 빨간 접시, 흰 접시 모두 **같은 자리**(로봇에서 약 0.97 m, 방향 +21~24°, 대략 x 0.90, y 0.35)에 둔다. 받침에 테이프로 표시해 둔다.
   - 흰 접시를 1.28 m(x 1.22)에 두면 경로가 전혀 나오지 않는다(10/19 오전).
   - 실행 중 `plate root [...] (r 0.97 m, 방향 +24 deg)` 줄로 확인할 수 있다.
7. **그리퍼**: 빈손으로 열어 둔다. 직접 명령할 때는 반드시 시스템 파이썬으로 실행한다(conda에는 pyserial이 없음).
   `/usr/bin/python3 ~/pan/6D_pose/calibration/gripper.py open`
8. **CPU**: Codex 계산(BK 지도 등)이 돌고 있으면 계획이 느려진다. 시연 중에는 Codex 계산을 멈춘다.
9. 비상정지를 손에 든다. 이동 45 °/s는 10/19 오후부터 쓴 속도다.

## 실행 중 화면

- `=== Q3 핀 front (red): 접시를 받침 위에 올려 두고 Enter (건너뛰기: s, 끝내기: q) ===` → 접시를 놓고 Enter.
- `Type exactly "area clear, e-stop in hand"`가 나오면 그대로 입력한다.
- 순서: 접시 인식 → `[basket] markers [2, 3, 4, 5]` / `marker z ... -> fixed 0.1440` → 후보 칸 → 잡기 → 들기 → 약 6초 정지(손 안 접시 자세로 다시 계산) → 30 cm 수직 상승 후 운반 → 바구니 위 → 7 °/s로 수직 넣기 → 놓기 → 손목 사진 → 홈.
- 실패하면 `!!! ... 실패 - 이 접시가 바구니에 꽂혀 남았으면 y, 아니면 Enter` → 실제로 꽂혀 있을 때만 y를 누른다.

## 문제가 생기면

| 화면 | 원인 | 조치 |
|---|---|---|
| `STOP: basket pose unreliable: 3 markers, residual ... mm` | 꽂힌 접시가 마커 일부를 가려 위치를 cm 단위로 잘못 읽음(두 번째 접시 때), 또는 마커 블록이 밀림 | 두 번째 접시는 첫 접시 때 4마커로 잰 바구니 위치를 30분까지 자동으로 다시 쓴다(`저장된 바구니 위치 사용`). 빈 바구니에서도 실패하면 `run.sh basket_check` |
| `MARKER BLOCK MOVED: 3 (robot_side) ...` (빈 바구니) | 마커 블록이 밀림 (10/19 16:4x 3·5번 약 2 cm) | 블록을 고정한 뒤 `bash calibration/run.sh basket_relayout` → y. **접시가 꽂혀 있을 때는 하지 않는다** |
| `basket marker fit z ... from the fixed 0.144` | 마커를 잘못 읽음 | 위와 같음 |
| `STOP: Q.. front/back: no pin with an insert plan` | 접시가 평소 자리가 아님, 또는 바구니가 움직임 | 접시를 테이프 자리에 놓고 다시 실행 |
| `ModuleNotFoundError: serial` | 그리퍼를 conda 파이썬으로 실행함 | `/usr/bin/python3 .../gripper.py ...` |
| `robot is .. deg from home` | 로봇이 홈 자세가 아님 | 펜던트로 홈에 둔 뒤 다시 실행 |
| 들어 올린 뒤 정지가 길다 | CPU가 다른 계산에 쓰임 | Codex 계산을 멈춤 |
| 접시를 든 채 멈춤 | — | 비상정지 상태를 보고 그리퍼를 열지 판단한다. 경로 다리 하나만 실행: `bash calibration/run.sh mover --plan <실행 폴더의 plan.json> --leg <다리 이름> --execute` |

## 아직 남은 위험 (10/19 기준)

- 바구니 위치를 마커로 잴 때 하루 안에서도 x 0.97~1.01, y −0.18~−0.23, yaw −0.4~2.5°로 흔들렸다. 4개가 모두 보이면 안정적이다.
- 착지가 겨냥한 칸에서 1~2칸 어긋날 수 있다(10번 겨냥 → 약 8번). 영역 방식이라 시연 성공 판정에는 영향이 없다.
  - Codex BL 결과, Q3 모델 오차는 2 mm 이내다. 원인으로는 겨냥 x 이동(−3.84 cm ≈ 2칸)을 의심한다. 시연 뒤 확인한다.
- Q4 바구니 모델은 실측과 1.3~2.2 cm 다르다. 시연 뒤 반영한다.
