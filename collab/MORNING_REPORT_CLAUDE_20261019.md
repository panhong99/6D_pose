## 2. 업무 설계
**셀 재보정 (튜닝 아님, 측정)**
- 고정카메라 재캘리브레이션: 보스 측정 12곳 중 11곳(1곳은 G·F 사이 마커 이동)으로 PnP. 재투영 평균 2.1 px. 결과 폴더 `real_handeye/20261016_134701_fromwrist_drop3`(그리퍼가 87° 돌아간 상태로 잰 13:12 세션은 INVALID 표시 후 자동 선택에서 제외).
- 바구니 위치: 바구니가 +x 9 cm 이동 + 마커를 판에 다시 붙임 → 손목 사진 2장에 빗살 모델을 맞춰(chamfer) 바구니 위치 (1.010, −0.173, 2.2°) 결정, 마커 새 배치 저장.
- 마커 블록을 플래너 충돌 모델에 추가(14 cm 상자). 그 결과 Q3 4·5번은 넣기 경로 없음 → **목표 Q3·Q4 8번(뒤)·11번(앞)**.

**흰 접시 (opt-in, 기본은 빨간 접시 그대로)**
- `--plate_color white`: YOLOE "white plate" + 029 모양에 흰 텍스처. 잡기 1 cm 깊게, 그리퍼 힘 설정값 128(빨강 64). 설정값을 2배로 한 것이고 실제 쥐는 힘이 2배인지는 재지 않았다.
- 연속 시연: `DEMO_PINS="Q3:10 Q3:8:white Q4:10 Q4:8:white" bash calibration/run.sh demo4 --execute` (앞쪽 11→10번, 4절 참고)

**넣기 보정 PPO (학습)** — 지난주와 같은 구조(한 번 넣기 = 1스텝, 출력 5개: x·y 겨냥, 기울임, 깊이, yaw)
- 학습 배치를 오늘 바구니 자리 주변(x 0.96–1.06 m)으로 새로 만듦. 기존 학습은 x 0.76–0.86이라 실기 바구니(0.92→1.01)가 범위 밖이었다.
- 실기에서 본 칸 어긋남(목표 6 → 3.5, 약 4.4 cm)은 sim 랜덤화(±8 mm)보다 훨씬 크다. → 정책이 **칸 오차를 입력으로 보도록** 학습: 칸 오차 ±30 mm 섞고, 보는 값에 6 mm 잡음.
- 실기에서 칸 오차 입력 = 직전 실기에서 같은 칸을 노렸을 때 **실제로 들어간 칸**(`--insert_landed_pins`). 사람이 숫자를 고치는 대신 실측 결과를 정책이 받아 스스로 보정.

## 3. 실험 결과 (sim, 학습에 안 쓴 200개, Q3·Q4 8·11번, 전체 오차 + FP 잡음, 95% 구간)

| 칸 오차 크기 | 방식 | 성공률 |
|---|---|---|
| ±8 mm (기존 가정) | 튜닝 | 49.5% [42.6, 56.4] |
| | e3 (현 실기 후보) | 60.0% [53.1, 66.5] |
| | 8·11 전용 (칸 오차 못 봄) | 60.5% [53.6, 67.0] |

| | e3 | **29.0%** [23.2, 35.6] |
| | **칸 오차 보는 정책** | **59.0%** [52.1, 65.6] |

- 칸 오차가 실기처럼 크면 못 보는 방식은 24~29%로 무너지고, 칸 오차를 보는 정책은 59%를 유지한다(e3 대비 짝 비교 80승 20패).
- 칸 오차가 작을 때는 칸 오차 보는 정책이 e3보다 낮다(22승 33패). → 실기 첫 회 결과로 고른다.
- 앞쪽 목표를 10번으로 바꾼 세트(100개, ±30 mm)에서도 칸 오차 보는 정책 **64%** vs e3 **17%**(52승 5패) — 8·11번으로 학습했는데 이 100개 sim 표본에서는 10번에서도 차이가 유지됐다(실기 성능 입증은 아님, Codex 재집계 일치).
- 오늘 실기(보스): 흰 접시 Q3 6번 → 3·4 사이. 빨강 Q3 4·흰 Q3 9·빨강 Q4 4번 넣기 완료(칸 미기록), **Q4 4번에서 마커판 충돌**. 마지막 흰 접시는 접시가 x 1.215에 있어 잡기 경로를 컨트롤러가 거부.
