# 바구니 넣기 학습 계획 (2026-10-12 Claude 작성, 보스 검토 전)

## 출발점
- 실기 기준선: **티칭 + 사람 피드백 + 기하 보정, 학습 없음**. 10/12 넣기까지 간 12회 중 11회 성공(실패 1: 각도 모자라 핀 쌍과 어긋남). 라벨 `calibration/data/real_pipeline/labels_20261012.jsonl`.
- 데모: 실기 12회(손목 사진, 관절, 외력, FP), sim 전문가 데모 657개(옛 6 cm 수직 핀 모델 기준).
- 알려진 한계: 바구니가 지금 자리보다 멀면 도달 불가, 운반 경유점이 티칭 고정, 손 안 접시 자세가 매번 조금씩 달라짐(위에서 본 사진으로 안 보임).

## 목표 (보스 10/12)
1. **바구니 위치 자유도**: 접시 위치처럼 바구니도 범위 안 어디든.
2. **핀 쌍에 정확히 안착**: 넣을 틈의 두 핀 줄과 접시가 맞은 상태로 들어가기(실기 시연 참고).
3. 미세 조정(깊이·기울기 등)은 2와 같은 문제로 묶음.
- 접시 높이(받침 위)는 지금처럼 유지. 바닥 잡기는 이번 계획 밖.

## 원칙
- 운반(바구니 위까지)은 **경로 계획**(학습 아님). 학습은 바구니 위 → 넣기 → 놓기 구간.
- **IL 먼저, RL은 미세 조정(residual)**. 10/7 PPO 붕괴 교훈: BC 고정 + 작은 residual, 낮은 학습률, value loss 감시, 체크포인트 선택.
- 보상: 매 스텝 [−1, 1], 종료 보상 최대 ±10(보스 규칙). 속도 상한(TCP 5 cm/s, 회전 10°/s)은 env 안에.
- 단계마다 GUI와 수치로 보고하고, 보스 승인 뒤 다음 단계로 간다.

## 단계

**보스 10/12: 이번 주(10/16 금) 안에 끝낸다.** 범위를 줄이고 학습은 밤에 돌린다.

| 단계 | 내용 | 완료 기준 | 날짜 |
|---|---|---|---|
| **P0 정리·푸시** | 아래 정리 목록(필수만), 테스트, 푸시 | tests 통과, 1000줄 초과 0 | 10/13 오전 |
| **P1 sim = 실기** | 빗살 실측 USD, 실기 넣기 값(15°, +4 cm, 깊이, 속도), FP 기반 손 안 접시를 sim 전문가에. 실기 12회 바구니·잡기로 sim 재생 | 학습 아님, sim 검증: 실기 12회의 조건(바구니 위치·잡은 자세)마다 64 env(작은 잡음)로 재생 → 성공 11조건 중 ≥ 9조건에서 sim 성공률 ≥ 80% | 10/13 오후 |
| **P2 바구니 자유도** | 운반 = 경로 계획(경유점 계산 + 바구니 충돌 검사), 넣기 자세 후보 탐색(기울임·회전·롤)으로 바구니 위치마다 닿는 방법 선택. 바구니 pose 무작위 전문가 데모(clean + DART) 수집 → **밤에 BC** | sim 성공 지도, BC ≥ 85% | 10/14 (BC는 10/14 밤) |
| **P3 핀 쌍 안착 (residual RL)** | BC 고정 + 작은 residual PPO, 상태 관측(핀 쌍 기준 최저점 오차, 기울기·회전, 높이, 외력), 손 안 ±5 mm/±5°, 바구니 ±5 mm 무작위. **반복 상한 고정, 밤 1회** | sim ≥ 90% 그리고 BC보다 높음. 못 넘으면 BC만 쓴다 | 10/15 (학습은 10/15 밤) |
| **P4 실기** | 넣기 직전 정지점에서 측정(마커 + FP 손 안 자세) → sim rollout → 관절 경로 → mover(목표 1 방식) | 실기 10회 ≥ 기준선 11/12, 새 바구니 위치 포함 | 10/16 |

**이번 주에서 뺀 것(다음 주):** 손목 카메라 학생 정책 증류, 기울기가 보이는 두 번째 사진의 추정기, 여러 접시, 바닥 잡기. 이번 주 실기 관측은 마커 + FP(잡을 때 손 안 자세) 상태값으로 한다.

### 학습 설정 (초안)

**P2 BC (IL)**
| 항목 | 값 |
|---|---|
| 데이터 | sim 피드백 전문가, 바구니 pose 무작위(x ±10 cm, y ±15 cm, yaw ±15°, 도달 가능 범위 안), 성공 에피소드만: clean 1,500 + DART 1,500(실행 행동에 잡음, 라벨은 전문가 행동). 구간 = 바구니 위 → 놓기, 30 Hz, 에피소드 약 400 스텝 → 약 120만 프레임. 에피소드 10%는 검증용 |
| 관측(약 20차원, 정규화) | 핀 쌍 틈 기준 접시 최저점 (x, y, z), 접시 법선, 공구 축, 슬롯 기준 TCP, 레일 위 높이, 외력, 놓음 여부. 관절값·이전 행동·손가락은 숨김(copycat 교훈) |
| 행동 | 슬롯 좌표계 TCP Δ(위치 3 + 회전 3, 스텝당 1.7 mm·0.33° 상한 = 5 cm/s·10°/s) + 그리퍼 열기 |
| 망 | MLP [512, 256, 128], ELU (PPO actor와 같은 모양) |
| criterion | 연속 행동: MSE(정규화 단위), 그리퍼: BCE. 핀 근처(레일 위 4 cm 이하) 프레임 3배 가중 |
| optim | AdamW, lr 1e-3 → cosine으로 1e-5, weight decay 1e-5, batch 4,096, grad clip 1.0 |
| 반복 | 최대 60,000 step(약 200 epoch, GPU 몇 분). 검증 loss 조기 종료(5,000 step 동안 개선 없으면 멈춤), 10,000 step마다 sim 평가(128 env)로 체크포인트 선택, seed 3개 |
| 평가 | 512 env, 바구니 pose 무작위, 결정적 행동. 기준 ≥ 85% |

**P3 residual RL (PPO, rsl_rl)**
| 항목 | 값 |
|---|---|
| 구조 | 실행 행동 = BC(고정) + 0.2 × residual. residual actor/critic [512, 256, 128] |
| env | 1,024(실기 FP와 GPU 공유 시 512) |
| PPO | num_steps_per_env 32, learning epochs 5, mini-batches 4, lr 2e-5 고정, clip 0.2, desired_kl 0.005, gamma 0.998, lambda 0.95, entropy 0, init_std 0.3, max_grad_norm 1.0 |
| 반복 | 최대 1,500 iteration(약 4,900만 스텝, 밤 1회). 250 iteration마다 결정적 평가(512 env) |
| 멈춤 조건 | BC 성공률보다 5%p 낮아지면 그 전 최고 체크포인트로 되돌림, value loss가 처음의 10배 넘으면 중단, 최종은 평가 최고 체크포인트 |
| 기준 | ≥ 90% 그리고 BC보다 높음. 못 넘으면 BC만 실기에 |

### 알고리즘과 망의 관계
- **망(MLP)** = 정책 함수 π(관측) → 행동. 관측 약 20차원을 받아 행동 7차원을 내는 [512, 256, 128] 완전연결망.
- **P2 알고리즘 = BC(행동 복제)**: 전문가 데모의 (관측, 행동) 쌍으로 이 MLP를 지도학습(회귀). 손실 MSE/BCE, AdamW. DART는 데이터 수집 방법(실행에만 잡음)이다.
- **P3 알고리즘 = PPO(actor-critic)**: BC MLP는 고정. 새 actor MLP가 보정량을 내고 실행 행동 = BC 출력 + 0.2 × 보정. critic MLP는 상태 가치를 내서 GAE로 advantage를 계산하고, actor는 clip 목적함수로 갱신.

### W&B (P0에서 정리)
- 학습 1개 = run 1개. BC는 seed마다 1개(같은 group), RL은 1개이고 chunk·재시작은 같은 run id로 이어 쓴다(새 run을 만들지 않음).
- 기록 항목만: BC는 train loss, val loss, lr, grad norm, sim 성공률(평가 때). RL은 평균 보상, 성공률, value loss, policy loss, KL, lr, action std.
- 일회성 스크립트의 W&B 코드는 정리하면서 지운다. 웹에 있는 기존 run 삭제는 목록을 보스에게 보여 주고 확인받은 뒤.

### 안전장치 (시간 낭비 방지)
**시작 전 (실패하면 본 학습 안 함, 각 10분 이내)**
- 데이터 검사: 에피소드 수, 성공 라벨, 행동 범위(속도 상한 안), NaN 없음, 관측 차원.
- 작은 배치 과적합 시험: 256 프레임에 1,000 step → train loss가 거의 0이 안 되면 코드 버그로 보고 중단.
- RL 사전 시험 20 iteration: 보정 0일 때 성공률이 BC 평가와 같은지, 보상·loss에 NaN 없는지.

**BC 학습 중**
- 조기 종료 patience: val loss가 5,000 step(약 17 epoch) 동안 0.5% 넘게 안 줄면 멈춤, 최고 val 체크포인트 사용.
- 기준선: "평균 행동만 내는 모델"의 val loss 대비 비율(R²)을 같이 기록 → R² < 0.5면 과소적합.

**RL 학습 중**
- patience: 250 iteration마다 결정적 평가, 2번 연속(500 iteration) 최고 성공률을 못 넘으면 멈춤.
- 되돌림: BC보다 5%p 낮아지면 최고 체크포인트에서 재개(1회만), 두 번째면 중단.
- 중단: value loss > 처음 × 10, KL > 0.05가 연속, action std < 0.02(탐색 소멸) 또는 > 1.0, NaN.
- 시간 상한: 실시간 6시간, 1,500 iteration. 로그가 15분 멈추면 watchdog가 종료.
- 판정은 보상이 아니라 결정적 평가 성공률로(보상 해킹 방지).

**끝나면**: 곡선 그림(PNG) + W&B 링크 + 판정(진행/BC 유지/중단)을 LOG에 쓰고 보스에게 보고. 다음 단계는 보스 승인 후.

### 곡선 (W&B, 한 그래프에 비교되게)
| BC | RL |
|---|---|
| train loss와 val loss를 한 그래프에 | 결정적 평가 성공률 + BC 기준선(가로선) |
| val 행동 정확도(오차가 위치 0.5 mm·회전 0.1° 안인 비율), 그리퍼 정확도 | 평균 보상(스텝 / 에피소드) |
| R², lr, grad norm | value loss, policy loss, KL, action std, lr |

읽는 법: 둘 다 높고 평평 = 과소적합, train ↓ val ↑ = 과적합, 둘 다 일찍 평평하고 성공률도 정체 = 지역 최소(lr·데이터·관측 점검). RL에서 보상만 오르고 성공률이 안 오르면 보상 설계 문제.

### P3 보상 (초안)
- 매 스텝(합 [−1, 1]로 자름): −핀 틈 중심과 접시 최저점 거리, −기울기·회전 오차, −외력 초과분, −행동 크기, +하강 진행(정렬이 맞을 때만).
- 종료: 성공 +10(최저점이 핀 쌍 틈 안 + 목표 깊이 + 놓은 뒤 1 s 정지), 실패 −10(엉뚱한 칸, 접시 낙하, 외력 한계 초과, 시간 초과).
- 학습 종료 조건: 최대 반복 수와 sim 성공률 기준을 실행 전에 고정.

### 관측 문제 (실기 실패에서 배운 것)
- 위에서 본 손목 사진으로는 기울기 차이가 안 보임(성공 −3.7°, 실패 −3.4°). → 다음 주: 넣기 직전 **두 번째 시점**(비스듬히 1장) + sim 렌더로 추정기 학습. 이번 주는 손 안 자세를 FP 상태값으로 쓰고 RL 무작위화로 버티게 한다.
