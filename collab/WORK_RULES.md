# 업무 지침서 (Claude · Codex 공통, 보스 10/14)

작업 시작 시 `CLAUDE.md` 다음으로 이 문서를 읽는다. 이 문서가 `collab/TASKBOARD.md`의 운영 규칙보다 우선한다.

## 1. 계속 일한다 (쉬는 시간 없음)
- 에이전트에게 쉬는 시간은 없다. 쳇바퀴처럼 멈추지 않고 계속 일한다.
- 한 일이 끝나면 바로 다음 일을 시작한다.
- 일하는 중에 업데이트(보스 지시, 작업판 변경, 상대 에이전트 결과)가 들어오면 그 시점에 계획을 다시 세운다. 일이 끝나고 새 업무가 들어올 때도 같다.
- **30분마다 점검은 (보스 10/14 18:5x: 1시간 → 30분, LOG 진행 기록도 30분마다) 일하는 주기가 아니다.** 일하는 도중에 새 업데이트가 있는지 확인하는 주기다.
  - 새 업데이트가 있으면 지금 하는 일을 마친 뒤, 계획을 다시 세우고 새 일을 시작한다.
  - 새 업데이트가 없으면 하던 일을 계속한다.
- '30분에 한 번 잠깐 일하고 기록만 남기기'는 금지한다.

## 2. 맡은 일은 "완수"한다
- 목표는 적당히 하고 넘기는 것이 아니라 끝까지 완수하는 것이다. 적당히 끊고 넘길지는 **보스가 정한다**.
- 일마다 작업판에 완료 조건(무엇이 되면 끝인지, 수치 기준)을 적는다.
- **2시간 안에 끝나지 않을 때:**
  - 그 일이 다음 업무에 영향을 주지 않으면 지금까지의 결과와 남은 것을 기록하고 다음 업무로 넘어간다. 남은 것은 나중에 다시 이어서 완수한다.
  - 다음 업무가 그 일을 반드시 필요로 하면(선행 업무) **4시간까지** 계속한다.
  - 4시간이 지나도 안 되면 막힌 이유, 시도한 방법, 대안을 기록하고 보스 판단을 기다린다. 그동안 다른 일을 진행한다.
- 막히면 같은 방법을 반복하지 말고 방법을 바꿔 본다. 바꾼 방법도 기록한다.

## 3. 낮 일과 밤 일
- **낮 (보스가 있어야 하는 일):**
  - 실로봇·그리퍼 조작
  - 카메라·시각 처리 결과를 눈으로 확인하는 일(사진 속 핀 라벨, 인식 결과 검증 등)
  - 실기 결과 판정
  - 다음 목표 논의
- **밤 (에이전트끼리 하는 일):**
  - 코드 작성과 수정, 회귀 시험
  - 작성한 코드로 시뮬레이션(Isaac) 검증과 학습 돌리기. 예: 바구니 위치를 옮겨도 되는지, 접시를 여러 핀 번호에 꽂을 수 있는지
  - 자동으로 판정되는 수치(성공률, 오차 등)로 결과 정리
- 밤에 한 일은 다음 날 아침 보스에게 **GUI(그림, 영상, RViz/Isaac 화면) 또는 수치 표**로 보고한다. 보고 시각은 08:30이고, 진척과 상관없이 한다(무엇을 했고, 수치가 얼마였고, 무엇이 실패했는지).
- **보스는 매일 아침 `collab/LOG.md`만 읽는다.** 그래서 아침 보고는 LOG.md에 `## YYYY-MM-DD 아침 보고` 절로 쓴다. Claude와 Codex 결과를 Claude가 하나로 합쳐 쓴다.
  - 맨 위에 요약 3줄: 된 것 / 안 된 것 / 보스가 오늘 해야 할 것
  - 일별 결과 표: 일, 완료 조건, 결과 수치, 상태
  - 실패와 버그
  - 그림·영상 경로와 보스가 바로 실행할 명령(직접 확인한 것만)
- 사람 눈 판정이 필요한 일을 밤 작업으로 맡기지 않는다. 그런 일은 낮에 보스와 함께 한다.

## 4. 멈추지 않는 장치 (10/14 시험으로 확인)
- 10/13 밤 Claude가 12시간 멈춘 원인: 끝나지 않는 백그라운드 대기 명령 + **백그라운드 작업이 도는 동안에는 예약 알람(cron)이 울리지 않음**(10/14 10:00 시험: 감시 작업 중 알람 미발생, 감시 작업 완료 알림은 정상).
- **Claude 1순위 깨우기: `collab/watch_job.sh`.** 계산마다 감시를 걸고, 감시는 완료 / 죽음 / 20분 진행 없음 / 최대 30분 중 하나로 반드시 끝나며 Claude를 부른다. 불리면 상태를 확인하고 다시 건다.
- **할 일이 없어도 감시 없이 답장을 끝내지 않는다.** 감시는 항상 하나 이상 걸려 있어야 한다. 매시 알람은 감시가 없을 때만 울리는 2순위 안전장치다.
- 긴 계산은 세션과 분리해서(`nohup … & echo $!`) 띄운다. 감시는 PID와 시작 시각으로 하고, `pgrep -f` 같은 문자열 감시는 쓰지 않는다.
- 큰 계산 전에는 경계값을 포함한 일부를 먼저 돌려 성공을 확인한 뒤 전체를 돌린다.
- 커밋 전에 회귀 시험을 통과시킨다. 보스에게 주는 명령은 직접 확인한 것만 주고, 확인하지 못한 부분은 '확인 못 함'이라고 적는다.
- 승인 창 확인(10/14): 계산 띄우기, git 커밋, Isaac 실행 모두 승인 창 없이 실행된다.
- 밤에는 보스가 Claude에게 작업 권한을 위임한다. Claude가 작업 담당자이고, 0순위는 **Codex와 분업해서 주어진 작업을 완수**하는 것이다. Codex가 막히거나 늦으면 기다리지 말고 나눠 맡거나 직접 한다.
- 잠재 문제가 의심되면 낮에 보스가 있을 때 보고하고 미리 시험한다.

## 4-1. 주중 낮 Claude↔Codex 회전 (10/14 보스)
- Codex는 일이 끝나면 **반드시** 작업판 표 상태를 `완료(커밋 해시)`로 바꾸고 결과를 `LOG.md`에 적는다. 막히면 `막힘: 이유 / 시도 / 대안`.
- Claude는 `collab/watch_codex.sh`로 Codex를 지켜본다. Codex가 커밋하면 즉시, 아니면 **25분마다** 깨어나 Codex 결과를 검토하고, 끝난 일이 있으면 다음 일을 작업판에 올린다. 작업판에 남은 Codex 일이 2개 미만이 되지 않게 미리 채운다.

## 5. 기록
- 일을 시작할 때, 계획을 바꿀 때, 끝낼 때 작업판(`collab/TASKBOARD.md`)과 `collab/LOG.md`에 남긴다.
- 기록에는 수치와 경로를 함께 적는다.
- 실패와 버그도 숨기지 않고 적는다.

## 6. 공통 금지 (기존 규칙 유지)
- 실로봇·그리퍼 동작 명령은 보내지 않는다. 보스가 실행한다.
- 캘리브레이션 결과, 체크포인트, 데이터, 라이브러리를 덮어쓰지 않는다.
- 데이터와 가중치는 git에 넣지 않는다.
- 프로세스는 PID로만 종료한다.
- 사용자는 "보스"로 부른다.
